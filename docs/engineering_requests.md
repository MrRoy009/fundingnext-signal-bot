# Engineering requests from GATE 2 (Quant)

These are the code changes the Engineer must make before the GATE 2 specs (`docs/specs/`) can be
implemented and validated. None of them changes strategy logic; each one makes the specs computable,
makes live behaviour match the backtest, or makes the validation possible. Items marked **OWNER** need
owner approval first (COMMON section 13). Nothing here places, changes or closes orders: the bot stays
read-only.

| ID | Request | Reason | Owner approval |

Print them on the ticket: ORDER TYPE line, CHASE LIMIT / SKIP LEVEL in price and points, EXPIRY, and `MANUAL TIME EXIT: close at hh:mm UTC (15:45 New York) if still open`. Replace the symmetric "Skip if +/- tolerance" line with the protocol's own instruction (COMMON 7). Size lots on `sizing_entry` (chase limit or entry, COMMON 7) and print the worst-case RISK $. Add the new fields to signals.csv. | The symmetric 0.25 x ATR skip rule adversely selects about 40% of tickets; SES-IBX-01 needs pending stop orders; MR-TWAP-01 needs limit-or-better entries; printed risk must never be exceeded by a permitted fill. | **OWNER (O1)** |
